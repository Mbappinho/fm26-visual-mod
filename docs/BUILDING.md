# Building and testing

## Python installer and tests

Python 3.11+ (standard library only). From the repository root:

```bat
python -B -m unittest discover -s tests
```

All tests use synthetic data. A few tests exercise real local inputs (your FIFA 17 install, a downloaded BepInEx zip,
a reviewed plugin build) and skip themselves when those inputs are absent.

## Plugin (`FM26.VisualDiagnostics.dll`)

Requirements: .NET SDK 6.0 or newer, and the **IL2CPP interop assemblies generated by BepInEx from your own FM26
install**. Interop assemblies and BepInEx binaries are derived from / part of third-party software and are **never
committed** to this repository (`tools/leak_scan.py` fails on any `.dll`).

1. Install BepInEx be.788 into FM26 once (`python -m tools.fm26vm setup ...` or `python tools/deploy.py install`)
   and start FM26 once so BepInEx generates `BepInEx/interop/` in the game folder. Close FM26.
2. Build, pointing the project at the BepInEx core folder and at the generated interop folder:

```bat
dotnet build FM26.VisualDiagnostics.csproj -c Release ^
    -p:LoaderDir="<FM26 folder>\BepInEx\core" ^
    -p:InteropDir="<FM26 folder>\BepInEx\interop"
```

Without `-p:` overrides the project uses `.tools/bepinex-stage/BepInEx/core` (an unpacked BepInEx zip, git-ignored)
and `$(FM26Dir)/BepInEx/interop`, where `FM26Dir` defaults to the standard Steam location
`C:\Program Files (x86)\Steam\steamapps\common\Football Manager 26` (override with `-p:FM26Dir=...`).

The build cannot run in an environment without the interop assemblies (for example CI on a clean machine); this
is expected.

`tools/fm26vm/release.json` pins the SHA-256 of the reviewed release DLL. A self-built DLL has a different hash
(compiler timestamps/MVID): `setup --plugin` refuses it on purpose; use the release asset, or update the pin in your
own fork after reviewing your build.

## C# policy tests

`tests/PolicyTests` compiles the game-independent policy sources of `src/` against plain .NET 8 (no interop):

```bat
dotnet run --project tests/PolicyTests/PolicyTests.csproj
```

**Known limitation of the public tree:** the suite currently stops with a `DirectoryNotFoundException` after the
first groups of checks pass. Some cases read maintainer-only inputs that are deliberately not published (recorded
FM26 match captures `tests/fixtures/fifa-overlay-live-*.json` and an older plugin source baseline used as a
regression reference). The project compiles and the game-independent checks that run before that point pass; the
full suite runs only in the maintainer checkout. `tests/HostSegments` is not published either.

## Verifying a build against the release

A Release build from this tree produces a DLL whose SHA-256 differs from the published asset (timestamp/MVID), but
its decompilation is identical. To check, decompile both with ILSpy (`ilspycmd -p -o <dir> <dll> -r <LoaderDir>
-r <InteropDir>`) and compare the generated `.cs` / `.csproj` files.
