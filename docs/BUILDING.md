# Building and Testing Guide

This guide details how to build and verify the components of **FM26 Visual Mod**: the Python installer and test suite, the C# BepInEx plugin, and the C# policy test suite.

---

## 1. Python Installer and Test Suite

The installer CLI and Python tools use the **Python standard library only** (tested with Python 3.14; Python 3.11+ supported).

Run the unit test suite from the repository root:

```bat
python -B -m unittest discover -s tests
```

> [!NOTE]
> All automated tests execute against synthetic test fixtures. Tests that interface with real game installations (such as your FIFA 17 files, local BepInEx archives, or staged plugins) automatically detect missing inputs and skip themselves gracefully.

---

## 2. Compiling the Plugin (`FM26.VisualDiagnostics.dll`)

### Prerequisites
- **.NET 8 SDK** (builds both the `net6.0` plugin and the `net8.0` policy tests).
- **IL2CPP interop assemblies** generated by BepInEx from your own Football Manager 26 installation.

> [!CAUTION]
> Interop assemblies and BepInEx binaries are derived from third-party proprietary software and are **never committed** to this repository. The security audit (`python -B tools/leak_scan.py . --tracked`) will fail if any `.dll` file is tracked by git.

### Build Steps

1. **Generate Interop Assemblies:**  
   Install BepInEx be.788 into FM26 once (via `python -m tools.fm26vm setup ...` or `python tools/deploy.py install`) and launch FM26 once. This prompts BepInEx to generate the `BepInEx/interop/` folder inside your game directory. Close FM26 once finished.

2. **Compile the Project:**  
   Build the project by specifying the BepInEx core loader path and generated interop assembly directory:

   ```bat
   dotnet build FM26.VisualDiagnostics.csproj -c Release ^
       -p:LoaderDir="<FM26 folder>\BepInEx\core" ^
       -p:InteropDir="<FM26 folder>\BepInEx\interop"
   ```

### MSBuild Properties Reference

| Property | Default Value | Description |
| :--- | :--- | :--- |
| `-p:LoaderDir` | `.tools/bepinex-stage/BepInEx/core` | Path to unpacked BepInEx core binaries. |
| `-p:InteropDir` | `$(FM26Dir)/BepInEx/interop` | Path to generated IL2CPP interop assemblies. |
| `-p:FM26Dir` | `C:\Program Files (x86)\Steam\steamapps\common\Football Manager 26` | Root installation path of Football Manager 26. |

> [!IMPORTANT]
> The plugin cannot be compiled in an environment lacking these local interop assemblies (e.g., standard clean-machine CI runners). This is intentional to ensure zero copyright infringement.

### Deterministic Build Guarantee

The compilation configuration enforces reproducible, deterministic builds:
- Flags enabled: `Deterministic`, `ContinuousIntegrationBuild`, `PathMap`, `DebugType=none`.
- No absolute PDB paths, timestamps, or local checkout directory names are embedded into the output binary.
- Compiling the same source tree with the same .NET SDK (release built with 8.0.425) and identical reference assemblies produces a **byte-for-byte identical DLL**.

The expected SHA-256 hash is pinned in `tools/fm26vm/release.json`. If your locally compiled hash differs due to differing reference assemblies or SDK versions, `setup --plugin` will refuse it as a safeguard. Use the pre-built release asset, or update the pin in your private fork after review.

## 3. C# Policy Test Suite

`tests/PolicyTests` verifies game-independent policy code in `src/` against vanilla .NET 8 (without requiring any game interop assemblies):

```bat
dotnet run --project tests/PolicyTests/PolicyTests.csproj
```

- Requires only the .NET 8 SDK and tracked files in this repository.
- Exits with return code `0` when all policy checks succeed.
- Evaluates against published synthetic fixtures (`tests/fixtures/fifa-overlay-live-001..004.*.json`, containing renderer flags, coordinates, and timer ticks) and `tests/fixtures/baseline-0.2.12/SemanticEventObserver.cs` (regression baseline).

---

## 4. Verifying Build Equivalence

If a release build from your environment does not match the published release byte-for-byte due to compiler or environment differences, its decompiled syntax should remain identical.

To verify equivalence:
1. Decompile both DLLs using [ILSpy CLI](https://github.com/icsharpcode/ILSpy):
   ```bat
   ilspycmd -p -o <output_dir> <dll_path> -r <LoaderDir> -r <InteropDir>
   ```
2. Run a diff on the resulting `.cs` and `.csproj` source trees to confirm structural parity.
